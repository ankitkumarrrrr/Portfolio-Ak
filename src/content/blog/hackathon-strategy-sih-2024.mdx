## Technical Decisions (Made in First 2 Hours)

### 1. Boring Stack, Bold Features

```
Frontend:  Next.js 14 + TypeScript + Tailwind + shadcn/ui
Backend:   FastAPI + PostgreSQL + Redis
ML:        Sentence-BERT embeddings + FAISS + LightGBM
Infra:     Docker + Railway (zero-config deploy)
Auth:      Clerk (drop-in, handles everything)
```

No Kubernetes, no microservices, no custom auth. Every minute on infra was a minute not building features.

### 2. Adaptive Learning = Retrieval + Reranking

We didn't train a custom model. We used a **two-stage pipeline**:

```
Student Query → Embedding (Sentence-BERT) → FAISS Vector Search (Top-50)
                                    ↓
                            LightGBM Reranker (features: difficulty, topic match, 
                                              student history, prerequisite graph)
                                    ↓
                            Top-5 Personalized Recommendations
```

**Why this worked:** 
- FAISS = sub-millisecond retrieval at scale
- LightGBM = interpretable, fast inference, handles tabular features natively
- Prerequisite graph = explicit knowledge structure (we built this from NCERT syllabus)

### 3. Prerequisite Graph from Syllabus

```python
# ml/prerequisite_graph.py
import networkx as nx
from sentence_transformers import SentenceTransformer

# Parse NCERT chapters → concepts → prerequisites
G = nx.DiGraph()

# Example: "Quadratic Equations" requires "Linear Equations", "Polynomials"
G.add_edge("Linear Equations", "Quadratic Equations")
G.add_edge("Polynomials", "Quadratic Equations")
G.add_edge("Quadratic Equations", "Discriminant")
G.add_edge("Quadratic Equations", "Nature of Roots")

def get_learning_path(student_mastery: dict, target_concept: str) -> list[str]:
    """Topological sort of missing prerequisites"""
    missing = [c for c in nx.ancestors(G, target_concept) 
               if student_mastery.get(c, 0) < 0.7]
    return list(nx.topological_sort(G.subgraph(missing)))
```

This gave us **explainable recommendations**: "You should review Linear Equations before Quadratic Equations" — not "the model thinks you need this."

## Judge Q&A Preparation

Ananya prepared answers for these (they asked 8 of 20):

| Question | Our Answer |
|----------|------------|
| "How do you handle cold start for new students?" | "Diagnostic quiz (5 questions) → initial mastery vector → Bayesian update as they interact." |
| "What if the prerequisite graph is wrong?" | "Graph is editable by teachers. We also learn edge weights from student success data." |
| "How does this scale to 1M students?" | "FAISS scales to billions of vectors. LightGBM inference is under 5ms. Stateless API = horizontal scaling." |
| "What about non-STEM subjects?" | "Embedding model is domain-agnostic. Prerequisite graph is the only domain-specific component." |
| "How do you measure learning gain?" | "Pre/post assessment on same concept cluster. RCTs planned with partner schools." |
| "What's your moat?" | "Not the model — the structured prerequisite graph + mastery tracking + teacher workflow." |
| "How do you handle hallucination in content generation?" | "We don't generate content. We retrieve and sequence *verified* NCERT content." |
| "What's the business model?" | "B2B: schools pay per student. B2C: freemium with advanced analytics." |

## Team Dynamics That Worked

1. **Daily 15-min standups** — Even at 3 AM. What did you do? What's next? Blockers?
2. **Pair programming on critical path** — Me + Rahul on ML pipeline; Priya + Ananya on demo flow.
3. **No heroics** — If someone was stuck >30 min, they asked. We swapped tasks freely.
4. **Protected sleep** — 4 hours each, staggered. No all-nighters. Cognitive function > lines of code.
5. **Ananya owned "external"** — Judges, mentors, organizers, food, logistics. We coded.

## What We'd Do Differently

1. **Earlier synthetic data generation** — LightGBM training data took 6 hours. Should've started at hour 2.
2. **More realistic personas** — Our seed users were too clean. Real students have messier histories.
3. **Accessibility audit** — We missed contrast ratios and keyboard nav. Judges didn't ask, but we knew.
4. **Load testing** — We assumed Railway would handle it. Should've run `locust` against the API.
