Chess engines are either too weak (naive minimax) or too opaque (Stockfish NNUE at 50k lines of C++). Learning developers need a readable, extensible engine that demonstrates core AI concepts without the complexity tax. This is that engine.

## Why From Scratch?

Stockfish is magnificent but impenetrable for learning. The magic bitboard implementation alone is 2,000+ lines of preprocessor macros. A from-scratch Python engine forces you to understand every component:

1. **Board representation** — How to encode 64 squares efficiently
2. **Move generation** — Legal moves for every piece type
3. **Search** — Minimax with alpha-beta pruning
4. **Evaluation** — Heuristic position scoring
5. **Time management** — Iterative deepening

## Bitboard Representation

A bitboard is a `uint64` where each bit represents a square. 12 bitboards = 6 piece types × 2 colors.

```
Bit 0  = a1    Bit 63 = h8
Bit 7  = a2    Bit 56 = h1
...
```

```python
# board/bitboards.py
from dataclasses import dataclass
import numpy as np

@dataclass
class BitboardBoard:
    # White pieces
    wp: np.uint64 = 0  # White pawns
    wn: np.uint64 = 0  # White knights
    wb: np.uint64 = 0  # White bishops
    wr: np.uint64 = 0  # White rooks
    wq: np.uint64 = 0  # White queens
    wk: np.uint64 = 0  # White king
    
    # Black pieces
    bp: np.uint64 = 0
    bn: np.uint64 = 0
    bb: np.uint64 = 0
    br: np.uint64 = 0
    bq: np.uint64 = 0
    bk: np.uint64 = 0
    
    # Occupancy
    white_occ: np.uint64 = 0
    black_occ: np.uint64 = 0
    all_occ: np.uint64 = 0
    
    # Game state
    side_to_move: bool = True  # True = White
    castling_rights: int = 0   # Bitmask: KQkq
    en_passant_square: int = -1
    halfmove_clock: int = 0
    fullmove_number: int = 1
```

**Why bitboards?**
- O(1) occupancy checks: `all_occ & (1 << square)`
- Parallel ray attacks with bitwise ops
- Hardware popcount (`bit_count()`) for mobility
- Compact: 12 × 8 bytes = 96 bytes for full position

## Magic Bitboards for Sliding Pieces

The trick: precompute all possible ray attacks for every square and occupancy pattern using "magic numbers."

```python

        ...

def bishop_attacks(square: int, occupancy: np.uint64) -> np.uint64:
    """O(1) bishop attacks on current occupancy"""
    mask = BISHOP_MASKS[square]
    magic = BISHOP_MAGICS[square]
    shift = BISHOP_SHIFTS[square]
    idx = ((occupancy & mask) * magic) >> shift
    return BISHOP_ATTACKS[square][idx]
```

**Initialization cost:** ~200ms at startup. **Query cost:** 3 integer ops. Worth it.

## Move Generation

Generate pseudo-legal moves, filter for legality (king not in check) during search.

```python
# movegen/generator.py
def generate_moves(board: BitboardBoard) -> list[Move]:
    moves = []
    side = board.side_to_move
    own_occ = board.white_occ if side else board.black_occ
    opp_occ = board.black_occ if side else board.white_occ
    all_occ = board.all_occ
    
    # Pawns
    pawn_bb = board.wp if side else board.bp
    moves.extend(gen_pawn_moves(pawn_bb, own_occ, opp_occ, all_occ, side))
    
    # Knights
    knight_bb = board.wn if side else board.bn
    moves.extend(gen_knight_moves(knight_bb, own_occ, opp_occ))
    
    # Bishops
    bishop_bb = board.wb if side else board.bb
    moves.extend(gen_sliding_moves(bishop_bb, own_occ, opp_occ, all_occ, bishop_attacks))
    
    # Rooks
    rook_bb = board.wr if side else board.br
    moves.extend(gen_sliding_moves(rook_bb, own_occ, opp_occ, all_occ, rook_attacks))
    
    # Queens (bishop + rook)
    queen_bb = board.wq if side else board.bq
    moves.extend(gen_sliding_moves(queen_bb, own_occ, opp_occ, all_occ, queen_attacks))
    
    # King
    king_sq = (board.wk if side else board.bk).bit_length() - 1
    moves.extend(gen_king_moves(king_sq, own_occ, opp_occ, all_occ, board))

    moves.extend(gen_castling_moves(board))

```

**Move encoding:** 16-bit integer — `from_square (6) | to_square (6) | promotion (2) | flags (2)`

## Minimax with Alpha-Beta Pruning

Standard recursive search with the key optimizations:

```python
# search/alphabeta.py
INF = 100000
MATE_SCORE = 32000

def search(board: BitboardBoard, depth: int, alpha: int, beta: int, 
           ply: int = 0, tt: TranspositionTable = None) -> int:
    
    # Transposition table lookup
    if tt:
        entry = tt.probe(board.zobrist_hash())
        if entry and entry.depth >= depth:
            if entry.flag == EXACT:
                return entry.score
            elif entry.flag == LOWER_BOUND:
                alpha = max(alpha, entry.score)
            elif entry.flag == UPPER_BOUND:
                beta = min(beta, entry.score)
            if alpha >= beta:
                return entry.score
    
    # Terminal / depth check
    if depth == 0:
        return quiescence(board, alpha, beta, ply)
    
    moves = generate_moves(board)
    if not moves:
        return -MATE_SCORE + ply if in_check(board) else 0  # Mate or stalemate
    
    # Move ordering (critical for alpha-beta efficiency)
    moves = order_moves(moves, board, tt, ply)
    
    best_score = -INF
    best_move = None
    
    for move in moves:
        board.make_move(move)
        score = -search(board, depth - 1, -beta, -alpha, ply + 1, tt)
        board.unmake_move()
        
        if score > best_score:
            best_score = score
            best_move = move
        
        alpha = max(alpha, score)
        if alpha >= beta:
            # Beta cutoff - store in TT
            if tt:
                tt.store(board.zobrist_hash(), depth, beta, LOWER_BOUND, move)
            return beta
    
    # Store in TT
    if tt:
        flag = EXACT if best_score > alpha and best_score < beta else UPPER_BOUND
        tt.store(board.zobrist_hash(), depth, best_score, flag, best_move)
    
    return best_score
```

## Move Ordering: The Secret to Alpha-Beta Efficiency

Alpha-beta's branching factor drops from ~35 to ~6 *with good ordering*. The hierarchy:

```python
def order_moves(moves: list[Move], board: BitboardBoard, tt: TranspositionTable, ply: int) -> list[Move]:
    scored = []
    
    for move in moves:
        score = 0
        
        # 1. Transposition table move (best from previous search)
        if tt and move == tt.get_best_move(board.zobrist_hash()):
            score += 10000
        
        # 2. Captures: MVV-LVA (Most Valuable Victim - Least Valuable Attacker)
        elif is_capture(move):
            victim_val = PIECE_VALUES[move.captured_piece]
            attacker_val = PIECE_VALUES[move.moving_piece]
            score += 1000 + victim_val * 10 - attacker_val
        
        # 3. Killer moves (non-captures that caused beta cutoff at same ply)
        elif move == killer_moves[ply][0]:
            score += 500
        elif move == killer_moves[ply][1]:
            score += 400
        
        # 4. History heuristic (moves that worked well in other branches)
        else:
            score += history_table[move.from_sq][move.to_sq]
        
        scored.append((score, move))
    
    scored.sort(reverse=True, key=lambda x: x[0])
    return [m for _, m in scored]
```

**MVV-LVA** ensures we try capturing the queen with a pawn before capturing a pawn with a queen.

## Iterative Deepening + Aspiration Windows

```python
# search/iterative.py
def iterative_deepening(board: BitboardBoard, max_depth: int, time_limit: float) -> Move:
    start_time = time.time()
    best_move = None
    prev_score = 0
    
    for depth in range(1, max_depth + 1):
        # Aspiration window around previous score
        alpha = prev_score - 50
        beta = prev_score + 50
        
        while True:
            score = search(board, depth, alpha, beta, 0, tt)
            
            if score <= alpha:
                alpha = -INF  # Re-search with wider window
                beta = prev_score + 50
            elif score >= beta:
                beta = INF
                alpha = prev_score - 50
            else:
                break  # Score within window
        
        prev_score = score
        best_move = tt.get_best_move(board.zobrist_hash())
        
        # Time check
        if time.time() - start_time > time_limit * 0.8:
            break
    
    return best_move
```

**Aspiration windows** reduce search by 20-30% by narrowing alpha-beta bounds around expected score.

## Evaluation Function

Greedy but effective: material + piece-square tables + pawn structure + king safety + mobility.

```python
# eval/evaluate.py
PIECE_VALUES = {
    PAWN: 100, KNIGHT: 320, BISHOP: 330, ROOK: 500, QUEEN: 900, KING: 20000
}

# Piece-square tables (centipawns) - simplified
PAWN_PST = [
     0,  0,  0,  0,  0,  0,  0,  0,
    50, 50, 50, 50, 50, 50, 50, 50,
    10, 10, 20, 30, 30, 20, 10, 10,
     5,  5, 10, 25, 25, 10,  5,  5,
     0,  0,  0, 20, 20,  0,  0,  0,
     5, -5, -10, 0, 0, -10, -5,  5,
     5,  5, 10, -20, -20, 10, 5, 5,
     0,  0,  0,  0,  0,  0,  0,  0
]

def evaluate(board: BitboardBoard) -> int:
    score = 0
    
    # Material + PST
    for piece_type, value in PIECE_VALUES.items():
        white_bb = getattr(board, f'w{piece_type[0].lower()}')
        black_bb = getattr(board, f'b{piece_type[0].lower()}')
        
        pst = PIECE_SQUARE_TABLES[piece_type]
        score += value * (white_bb.bit_count() - black_bb.bit_count())
        score += popcount_weighted(white_bb, pst) - popcount_weighted(black_bb, reversed_pst(pst))
    
    # Pawn structure: doubled, isolated, passed
    score += evaluate_pawn_structure(board)
    
    # King safety: pawn shield, open files near king
    score += evaluate_king_safety(board)
    
    # Mobility: legal move count weighted by piece
    score += evaluate_mobility(board)
    
    return score if board.side_to_move else -score
```

## Transposition Table (Zobrist Hashing)

```python
# search/tt.py
import random

# Precomputed random numbers: [piece_type][color][square]
ZOBRIST_PIECES = [[[random.getrandbits(64) for _ in range(64)] for _ in range(2)] for _ in range(6)]
ZOBRIST_SIDE = random.getrandbits(64)
ZOBRIST_CASTLING = [random.getrandbits(64) for _ in range(16)]
ZOBRIST_EP = [random.getrandbits(64) for _ in range(8)]

def compute_zobrist(board: BitboardBoard) -> int:
    h = 0
    for piece_idx, piece_attr in enumerate(['wp','wn','wb','wr','wq','wk','bp','bn','bb','br','bq','bk']):
        bb = getattr(board, piece_attr)
        color = 0 if piece_idx < 6 else 1
        piece_type = piece_idx % 6
        while bb:
            sq = (bb & -bb).bit_length() - 1
            h ^= ZOBRIST_PIECES[piece_type][color][sq]
            bb &= bb - 1
    
    if not board.side_to_move:
        h ^= ZOBRIST_SIDE
    h ^= ZOBRIST_CASTLING[board.castling_rights]
    if board.en_passant_square != -1:
        h ^= ZOBRIST_EP[board.en_passant_square % 8]
    
    return h

class TranspositionTable:
    def __init__(self, size_mb: int = 64):
        self.size = (size_mb * 1024 * 1024) // 16  # 16 bytes per entry
        self.table = [0] * self.size
    
    def store(self, key: int, depth: int, score: int, flag: int, move: Move):
        idx = key % self.size
        self.table[idx] = Entry(key, depth, score, flag, move)
    
    def probe(self, key: int) -> Entry | None:
        idx = key % self.size
        entry = self.table[idx]
        return entry if entry.key == key else None
```

## Key Learnings

1. **Move ordering is everything** — A well-tuned depth-4 search beats a poorly-tuned depth-6. MVV-LVA + killers + history = 10× speedup.
2. **Bitboards + alpha-beta is the "hello world" of game AI** — But the devil is in the details: move ordering, evaluation tuning, time management.
3. **Readable code enables experimentation** — This engine became a testbed for ML-based evaluation later. Clean separation of concerns (board, movegen, search, eval) made swapping components trivial.
4. **Python is fast enough for depth 6** — With `@lru_cache`, `array.array`, and `multiprocessing` for root splitting. The bottleneck is move generation, not search.
