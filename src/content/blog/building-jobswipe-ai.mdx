JobSwipe AI started from a simple frustration: job hunting is a terrible user experience for candidates. You spend hours tailoring resumes, manually searching scattered job boards, and cold-emailing recruiters with abysmal response rates. Existing platforms optimize for employer workflows, not candidate efficiency.

## The Core Idea

What if candidates could just **swipe** — like Tinder — and an AI handles everything else? Parse the resume, find matching jobs, identify recruiters, write personalized pitches, and send them. One right-swipe → one tailored application sent.

## Resume Parsing with Gemini

The key insight: **don't just extract text, extract structured skill vectors**.

```typescript
// lib/gemini/resume-parser.ts
const RESUME_PARSING_PROMPT = `
You are an expert technical recruiter. Parse the resume and output JSON:

{
  "skills": [
    { "name": "React", "category": "frontend", "proficiency": "expert", "years": 4 },
    { "name": "PostgreSQL", "category": "database", "proficiency": "advanced", "years": 3 }
  ],
  "experience": [
    { "role": "Senior Engineer", "company": "Acme Corp", "duration": "2 years", "highlights": ["..."] }
  ],
  "education": [{ "degree": "BS Computer Science", "school": "MIT", "year": 2020 }],
  "summary": "Full-stack engineer specializing in..."
}
`

export async function parseResume(pdfBuffer: Buffer) {
  const model = genAI.getGenerativeModel({ model: 'gemini-1.5-pro' })
  const result = await model.generateContent([
    RESUME_PARSING_PROMPT,
    { inlineData: { mimeType: 'application/pdf', data: pdfBuffer.toString('base64') } }
  ])
  return JSON.parse(result.response.text())
}
```

**Why Gemini 1.5 Pro?** The 1M token context window handles long resumes without chunking. The structured output mode gives reliable JSON.

## Real-Time Job Scraping

We ingest from 12 sources daily via Next.js cron jobs:

```typescript
// app/api/cron/scrape/route.ts
export async function GET() {
  const sources = [
    scrapeRemotive(),      // Official API
    scrapeHackerNews(),    // "Who is Hiring" threads
    scrapeWellfound(),     // AngelList
    scrapeYC(),            // YC job board
  ]

  const jobs = (await Promise.all(sources)).flat()
  
  // Deduplicate by company + role + location
  const unique = deduplicateJobs(jobs)
  
  // Compute embeddings for each job
  for (const job of unique) {
    job.embedding = await embedJobDescription(job.description)
  }
  
  await prisma.job.createMany({ data: unique, skipDuplicates: true })
  
  return Response.json({ count: unique.length })
}
```

**Rate limiting strategy:** Exponential backoff with jitter, request queues per domain, and respectful `robots.txt` compliance.

## The Matching Algorithm

Simple but effective: cosine similarity between resume skill vector and job description embedding.

```python
# matching/scorer.py
import numpy as np
from sklearn.metrics.pairwise import cosine_similarity

def score_match(resume_vector: np.ndarray, job_embedding: np.ndarray) -> float:
    """Return similarity score 0-1"""
    return float(cosine_similarity([resume_vector], [job_embedding])[0][0])

def find_matches(resume_vector: np.ndarray, jobs: List[Job], threshold: float = 0.85) -> List[Match]:
    scored = [(job, score_match(resume_vector, job.embedding)) for job in jobs]
    scored.sort(key=lambda x: x[1], reverse=True)
    return [Match(job=j, score=s) for j, s in scored if s >= threshold]
```

**Threshold tuning:** 0.85 balances precision/recall. Below 0.8 = noise. Above 0.9 = too few matches.

## Recruiter Email Discovery

The hardest part. We use a multi-strategy approach:

1. **Domain pattern matching** — `google.com` → `recruiting@google.com`, `careers@google.com`, `talent@google.com`
2. **Hunter.io / Apollo.io API** — when available
3. **LinkedIn profile scraping** — for specific hiring managers (opt-in only)
4. **Bounce verification** — NeverBounce API before sending

```typescript
// lib/email/finder.ts
const COMMON_RECRUITER_PATTERNS = [
  'recruiting@{domain}',
  'careers@{domain}',
  'talent@{domain}',
  'hiring@{domain}',
  'jobs@{domain}',
  'people@{domain}',
  'hr@{domain}',
]

export async function findRecruiterEmails(domain: string): Promise<string[]> {
  const candidates = COMMON_RECRUITER_PATTERNS.map(p => p.replace('{domain}', domain))
  const verified = await Promise.all(candidates.map(verifyEmail))
  return verified.filter(Boolean)
}
```

## The Swipe Interface

Framer Motion + gesture handling. The swipe isn't just UI — it's an **explicit intent signal** that dramatically improves training data quality.

```tsx
// components/SwipeCard.tsx
export function SwipeCard({ job, onSwipe }: SwipeCardProps) {
  const [offset, setOffset] = useMotionValue(0)
  const [rotation, setRotation] = useMotionValue(0)

  const handleDrag = useDrag(({ offset: { x } }) => {
    setOffset(x)
    setRotation(x * 0.03) // Subtle rotation
  })

  const handleDragEnd = ({ offset: { x } }) => {
    if (x > 100) onSwipe(job.id, 'right')    // Match!
    else if (x < -100) onSwipe(job.id, 'left') // Pass
    else { setOffset(0); setRotation(0) }    // Snap back
  }

  return (
    <motion.div
      drag="x"
      dragConstraints={{ left: -300, right: 300 }}
      dragElastic={0.2}
      onDrag={handleDrag}
      onDragEnd={handleDragEnd}
      style={{ x: offset, rotate: rotation }}
      className="swipe-card"
    >
      {/* Job card content */}
    </motion.div>
  )
}
```

## Key Learnings

1. **Human-in-the-loop beats full automation** — The swipe gesture provides high-quality labels for retraining the matcher.
2. **Email deliverability is a product feature** — Warm IPs, SPF/DKIM/DMARC, unsubscribe headers, and bounce handling are non-negotiable.
3. **LLM token limits are real** — Recursive chunking with overlap + vector averaging works better than naive truncation.
4. **Observability > features** — You can't improve what you can't measure. Every swipe, match, send, open, and reply is tracked.
